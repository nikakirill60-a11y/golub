# Blitz Remaster SDK

[English](README.md) | [Русский](README.ru.md)

`rempack` проверяет, собирает и показывает **Remaster Packages** (`.rempack`) — формат
модов Blitz Remaster. Он собран из того же кода чтения и проверки пакетов, что и
игра: пакет, принятый `rempack`, примет и игра той же версии, а сообщения
у них одинаковые.

SDK — один самодостаточный исполняемый файл, устанавливать .NET не нужно:

| Архив | Исполняемый файл |
| --- | --- |
| `BlitzRemasterSDK-<версия>-windows-x64.zip` | `rempack.exe` |
| `BlitzRemasterSDK-<версия>-linux-x64.zip` | `rempack` |

`rempack --version` показывает версию инструмента, версию формата пакетов и
возможности, которые загружает соответствующая игра.

## Быстрый старт

```sh
rempack validate my_mod                         # проверить папку так же, как игра
rempack pack my_mod                             # записать <id>-<версия>.rempack рядом с ней
rempack inspect author.my_mod-1.0.0.rempack --files
```

В Windows папка, перетащенная на `rempack.exe`, упаковывается, а перетащенный
`.rempack` показывается; окно остаётся открытым до нажатия Enter. Путь без команды в
командной строке работает так же.

## Команды

| Команда | Что делает |
| --- | --- |
| `rempack validate <папка\|файл.rempack>` | Проверяет папку мода или пакет ровно так же, как игра при установке мода. Папка для проверки упаковывается во временный файл; рядом с ней ничего не появляется. |
| `rempack pack <папка> [-o <файл>]` | Упаковывает папку и проверяет записанный пакет. Отклонённый пакет не сохраняется, а файл с тем же именем, если он был, остаётся нетронутым. |
| `rempack inspect <файл.rempack>` | Показывает id, версию, название, авторов, лицензию, содержимое, зависимости, заменяемый стандартный контент и размеры, затем отчёт проверки. |
| `rempack help [<команда>]` | Справка или подробности об одной команде. |

## Параметры

| Параметр | Значение |
| --- | --- |
| `-o`, `--output <файл>` | Куда `pack` записывает пакет. По умолчанию — `<id>-<версия>.rempack` рядом с папкой; если указана существующая папка, пакет с таким именем появится в ней; недостающие папки создаются. |
| `--strict` | Отклонять и пакет с предупреждениями. |
| `--json` | Вывести вместо текста один JSON-документ в стандартный вывод. |
| `--files` | `inspect`: список всех файлов с размером и размером в сжатом виде. |
| `-v`, `--verbose` | Показывать коды замечаний, технические подробности, пропущенные файлы и ссылки. |
| `--lang <en\|ru>` | Язык сообщений. Без него — `REMPACK_LANG`, затем язык системы (в Linux — `LC_ALL`, `LC_MESSAGES` или `LANG`): для русской системы русский, для любой другой английский. |
| `--no-color` | Без цвета. `NO_COLOR` делает то же; при перенаправлении вывода цвет тоже выключается. |
| `--version` | Версия инструмента и то, что загружает игра. |
| `-h`, `--help` | Справка. |

## Коды возврата

| Код | Значение |
| --- | --- |
| `0` | Принят: игра установит этот пакет (предупреждения допустимы без `--strict`). |
| `1` | Отклонён: ошибки, которые нужно исправить, перечислены в отчёте. |
| `2` | Неверная командная строка или указанный файл или папка не существует. |
| `3` | Не удалось записать файл, например пакет или его временный файл. |

## Что попадает в пакет

`pack` кладёт `rempack.json` в корень пакета, а каждый другой файл папки — под его
относительным путём. Поле `files` манифеста он заполняет SHA-256 каждого упакованного
файла; то, что там было в `rempack.json` папки, заменяется. Не попадают в пакет:

- имена, начинающиеся с точки (`.git/`, `.rempackignore`, `.DS_Store`), и мусор архиваторов
  (`Thumbs.db`, `desktop.ini`, `__MACOSX/`);
- символические ссылки и точки соединения: по ним никогда не ходят (`-v` их перечисляет);
- исходники редакторов и остатки: `*.rempack`, `*.tmp`, `*.bak`, `*~`, `*.blend`,
  `*.blend1`…`*.blend9`, `*.psd`, `*.kra`, `*.xcf`, `*.spp`, `*.sbs`;
- шаблоны из `.rempackignore` в корне папки.

`.rempackignore` пишется как `.gitignore`: один шаблон на строку, `#` начинает
комментарий, `*` и `?` не выходят за косую черту, а `**` выходит, `[abc]` — класс
символов, `/` в конце совпадает только с папками, `/` в любом другом месте привязывает
шаблон к корню, `!` возвращает файл, а побеждает последняя подходящая строка.
Регистр букв не важен, как и в путях пакета.

```gitignore
# исходники и заметки
source/
*.max
notes.txt
!textures/readme_textures.txt
```

В путях пакета допустимы только латинские буквы, цифры, `.`, `_` и `-` между прямыми
косыми чертами; имя не может начинаться или заканчиваться точкой и совпадать с
зарезервированным именем устройства Windows (`con`, `nul`, `com1`…). Путь — не длиннее
240 символов, одно имя — не длиннее 96. Два пути, отличающиеся только регистром, считаются
одним. Все такие проблемы выводятся за один запуск вместе с остальной проверкой.

## `rempack.json`

```json
{
  "format": "rempack",
  "formatVersion": 1,
  "id": "author.my_mod",
  "version": "1.0.0",
  "name": { "en": "My mod", "ru": "Мой мод" },
  "description": { "en": "What it adds.", "ru": "Что он добавляет." },
  "authors": ["Author"],
  "license": "CC-BY-4.0",
  "homepage": "https://example.org/my_mod",
  "game": { "minVersion": "2.0.0", "features": ["tanks@1"] },
  "dependencies": [{ "id": "author.base_pack", "version": "^1.2" }],
  "conflicts": [],
  "content": { "tanks": ["t34_custom"] },
  "overrides": []
}
```

| Поле | Правила |
| --- | --- |
| `format`, `formatVersion` | `"rempack"` и `1`. Для более новой версии формата нужна более новая игра. |
| `id` | `author.mod_name`: две части из строчных латинских букв и цифр, соединённых одиночными подчёркиваниями (автор — до 32 символов, имя — до 48). По нему мод узнают везде, поэтому не меняйте его между версиями. |
| `version` | Семантическая версия: `1.0.0`, `1.2.0-beta.1`. Игра сравнивает её с установленной версией мода, чтобы отличить обновление от отката. |
| `name` | Строка (по-английски) или объект с кодами языков (`en`, `ru`, `pt-BR`); английский обязателен. До 64 символов. |
| `description` | Необязательно, как `name`; до 2000 символов. |
| `authors` | Обязательно: от 1 до 16 имён. |
| `license`, `homepage` | Необязательно. `homepage` — только адрес `https://`. |
| `icon` | Необязательно: путь в пакете к PNG или JPEG до 1024 × 1024; без этого поля берётся `icon.png` из корня. |
| `previews` | Необязательно: до 8 картинок PNG или JPEG до 8192 × 8192. |
| `game.minVersion` | Самая старая версия игры, с которой работает мод. |
| `game.features` | Что моду нужно от игры, в виде `имя@версия`: `tanks@1`, `hangars@1`, `maps@1`, `overrides@1`. Игра без нужной возможности отклоняет пакет с просьбой обновить игру. |
| `dependencies`, `conflicts` | До 32 записей `{ "id", "version" }`. Версии записываются как в npm: `*`, `1.2.3`, `>=1.2 <2`, `^1.2`, `~1.2.3`, `1.x`, варианты через `\|\|`. |
| `content` | Локальные id (строчные буквы и цифры, соединённые одиночными подчёркиваниями, до 48 символов) добавляемых танков (`tanks`), ангаров (`hangars`) и карт (`maps`), до 256 каждого вида; всего хотя бы один. Каждый лежит в `tanks/<id>/tank.json`, `hangars/<id>/hangar.json` или `maps/<id>/map.json`, и для каждого вида нужна его возможность в `game.features`. |
| `overrides` | Стандартный контент, который заменяет мод: `stock:tank/<id>`, `stock:hangar/<id>` или `stock:map/<id>`; нужна `overrides@1`. Пока такой мод включён, игра по сети недоступна. |
| `files` | Заполняет `pack`; вручную не правьте. |

Незнакомое игре поле — предупреждение, чтобы опечатка не осталась незамеченной.
`locale/<язык>.json` могут содержать плоские таблицы строк мода (ключи из строчных
букв, цифр, `_` и `.`). `LICENSE`, `README`, `CHANGELOG`, `CREDITS` и `NOTICE` в корне (без
расширения, `.txt` или `.md`) путешествуют вместе с пакетом; любой другой файл, который
ничем не используется, даёт предупреждение.

Главные ограничения: пакет до 1 ГиБ (от 300 МБ он помечается как тяжёлый), 2 ГиБ в
распакованном виде, 20 000 файлов, 512 МиБ на файл.

## Вывод JSON

С `--json` каждая команда выводит в стандартный вывод один JSON-документ и больше
ничего, на языке сообщений. В каждом документе есть `tool`, `version`, `command`,
`language` и `ok`. Проверяющие команды добавляют:

| Поле | Значение |
| --- | --- |
| `status` | `accepted`, `heavy` (принят и помечен как большой) или `refused`. |
| `strict` | Был ли указан `--strict`. |
| `counts` | `errors`, `warnings` и `notes`. |
| `issues` | У каждого замечания `severity` (`error`, `warning`, `info`), `code`, `path`, `args`, локализованное `message` и необязательное `detail`. |
| `dropped` | Сколько замечаний не вошло после первых 500. |
| `needsNewerGame` | Загрузит ли пакет только более новая игра. |

`validate` добавляет `path`, `folder`, `skipped` и `links`; `pack` — `path`, `output`,
`written`, `files`, `size`, `unpacked`, `skipped` и `links`; `inspect` — `path`,
`manifest`, `sizes` (`archive`, `unpacked`, `files`) и `entries` (`path`, `size`,
`compressedSize`, `method`, `sha256`). При неверной командной строке или ошибке записи
документ содержит `ok: false`, `status` `usage` или `failed` и `error` с `code` и
`message`. `--version --json` перечисляет `formatVersion`, `gameVersion` и `features`.

## Сборка из исходников

Исходники SDK лежат в `Sdk/` репозитория игры; сам код пакетов компилируется
из `Assets/Blitz/Core/Mods`, а тесты пакетов игры запускаются и в тестовом проекте SDK.
С .NET 10 SDK:

```sh
dotnet test Sdk/Rempack.Sdk.slnx -c Release   # тесты SDK и пакетов игры
python3 Tools/sdk_build.py                    # оба архива в Build/Sdk/
```

`Tools/sdk_build.py` находит `dotnet` через `BLITZ_DOTNET`, `PATH` или `~/.dotnet`,
запускает тесты, публикует урезанные однофайловые исполняемые файлы для
`win-x64` и `linux-x64` и упаковывает каждый вместе с этими README. `--platform`
ограничивает сборку одной платформой, `--skip-tests` пропускает тесты. Подробности — в
[`BUILD.ru.md`](../BUILD.ru.md#sdk).
